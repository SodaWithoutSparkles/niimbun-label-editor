# Known issues

- Date: 2026-10-06

## Import image doesnt work — ✅ fixed (P1, 2026-10-07)

Expected: Image node -> select file -> click import -> OS image picker dialog opens and user can select an image file to import.

Actual: Click import -> no OS image picker dialog opens. Red error message appears in the console: "Choose an image file first."

## Unable to edit image node — ✅ fixed (P2, 2026-10-07)
Image node cannot be edited (e.g. changing the image file/url) after it has been imported. 

## Quantizer does not allow detailed configs — ✅ fixed (P5, 2026-10-08)
Cannot change strength/threshold of various dithering techniques. 

## False clipping reminder
Expected: Even when label width > print head, there should be *no* warning *if* nothing would be printed there anyway (e.g. if the label is blank in that area).

Actual: Even a blank label shows `Label exceeds the printhead (591 px wide vs 567 px). Printing may be clipped.` on B1 pro.

## False QR code warning — ✅ fixed (P6, 2026-10-08)
Expected: `https://example` should *not* cause a warning to be displayed. 

Actual: A warning flag is overlayed on the QR code node. Do not flag a qr code might be an invalid one just because it was an example url, because there are genuine usecases.

## Missing warrning center — ✅ fixed (P6, 2026-10-08)
Expected: user can have a list of all warnings in one place, and click on them to jump to the node that caused the warning.

Actual: No such warning center exists. User are left to guess why the warning is being displayed.

## Polygon tool is broken — ✅ fixed (P4, 2026-10-08)
Expected: Tool -> select polygon tool -> click to add points -> double click to finish polygon -> polygon is created.

Actual: Tool -> select polygon tool -> click -> a blank polygon with a blue box outline (control points) is created with a warning at top right corner. 
Suspecting the "blue box outline" is a default polygon with 4 points, and I am confused because it was so fine that I thought it was the control box outline. related to the `Unable to edit stroke width/fill/stroke,etc of shapes` issue.

## Unable to edit stroke width/fill/stroke,etc of shapes. — ✅ fixed (P3, 2026-10-08)
"This content is bound to a CSV or template. Switch the content source to edit it." Even when there's no csv or template attached. That field should be templatable but also allowed to be static.

## View -> grid is broken — ✅ fixed (P1, 2026-10-07)
Expected: View -> grid -> toggle on -> should show a grid overlay on the label. The overlay should be a grid of lines that are 1cm apart, and should be visible on the label regardless of zoom level.

Actual: View -> grid -> toggle on -> nothing happens. No grid overlay is shown.

## Settings -> screen dpi clamped while typing — ✅ fixed (P1, 2026-10-07)
Expected: user can delete the whole field, type a new value, then only apply clamping/verification on defocus or on pressing enter.
Actual: Default value is 96. User clicks backspace to delete the 6, snaps right back to 24.

## Settings -> screen dpi does not offer a way to easily calibrate
There should be a easier way to calibrate the screen dpi. For example, a button that says "Calibrate" and opens a dialog that shows a ruler and allows the user to adjust the dpi until the ruler matches a real world ruler.

## node -> resize control is not working — ✅ fixed (P1, 2026-10-07)
Click and drag the resize control on a text node -> the control node disappears but the text node does not resize. The text node should resize as the user drags the control.

Repro on text, image also happens under some conditions. 
Suspecting the control node is so small that the user is frequently missing it. The UI shows the resize mouse cursor but the user is not actually clicking on the control node.

## node -> resize is not WYSIWYG — ✅ fixed (P2, 2026-10-07)
Expected: user can click and drag the resize control on a image node, the preview should be what the user expected to get

Actual: user can click and drag the resize control on a image node, the preview works, but on release of the mouse, the image node snaps to a different size than what the preview showed, and the image moved. 
Suspecting the "moved" is due to the image node being resized from the center, but the preview shows the image being resized from the top left corner.
